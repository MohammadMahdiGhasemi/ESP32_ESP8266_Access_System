# سیستم دو بردی کنترل دسترسی، دما و حرکت

این بسته برای ESP32-WROOM-32 معمولی و NodeMCU ESP8266 تهیه شده است. ESP32 شبکهٔ Wi-Fi می‌سازد و NodeMCU به آن متصل می‌شود؛ مودم یا اینترنت لازم نیست. نمایشگر 1602 پیام‌های انگلیسی دارد.

## فایل‌ها

برای خواندن راحت راهنما، `START_HERE_FA.html` را با مرورگر باز کنید؛ فایل آفلاین است و اینترنت نمی‌خواهد.

- `ESP32_Master/ESP32_Master.ino`: نمایشگر، گیرندهٔ ریموت، بازر و شبکهٔ اصلی.
- `ESP8266_Node/ESP8266_Node.ino`: کارت‌خوان، حافظهٔ کارت، DHT11، حرکت و LEDها.
- `Core.h` در هر پوشه: منطق مشترک؛ همراه فایل ino نگه دارید.
- `tests/test_core.cpp`: آزمون رایانه‌ای منطق مشترک؛ برای آپلود لازم نیست.
- `VALIDATION.md`: نتیجهٔ بررسی‌های این نسخه و محدودیت آزمون.

## رفتار سیستم

| رویداد | نتیجه |
|---|---|
| حالت عادی | نمایش دما و رطوبت؛ خواندن DHT11 هر ۲٫۵ ثانیه |
| حرکت جدید | یک بوق و پیام Motion detected |
| کارت ناشناخته | LED قرمز، سه بوق و Access Denied |
| دکمهٔ ۱ | ورود به ثبت کارت پس از تأیید ESP8266؛ مهلت ۲۰ ثانیه |
| کارت جدید در حالت ثبت | ذخیرهٔ دائمی، LED سبز، دو بوق و Card saved |
| ثبت کارت تکراری | Already saved؛ بدون مصرف ظرفیت جدید |
| کارت ثبت‌شده | LED سبز، یک بوق و Access Granted |
| پایان مهلت | لغو ثبت و بازگشت به نمایش عادی |
| قطع ارتباط تشخیص‌داده‌شده | لغو ثبت؛ Node offline روی نمایشگر |
| حافظه یا فایل خراب | رد دسترسی؛ بدون پاک‌کردن خودکار کارت‌ها |

ظرفیت ۵۰ کارت است. قطع برق عادی کارت‌ها را پاک نمی‌کند. موفقیت ثبت فقط پس از نوشتن و خواندن دوبارهٔ فایل اعلام می‌شود. اطلاعات با CRC بررسی می‌شود و فایل موقت سپس جایگزین فایل اصلی می‌شود. این روش جای پشتیبان‌گیری یا آزمون قطع برق روی سخت‌افزار را نمی‌گیرد.

پس از قطع ارتباط، کارت‌های موجود همچنان در ESP8266 بررسی می‌شوند و LEDها کار می‌کنند؛ بوق و نمایش آن رویدادها روی برد خاموش/قطع‌شده ممکن نیست. رویدادهای زمان قطع ارتباط ذخیره و بعداً بازپخش نمی‌شوند. تشخیص قطع خاموش شبکه تا حدود ۶ ثانیه زمان می‌برد. اگر اتصال درست هنگام ثبت قطع شود، ممکن است کارت ذخیره شده باشد ولی پیام موفقیت نرسد؛ بعد از اتصال دوباره کارت را امتحان کنید.

حرکت بر مبنای تغییر خروجی PIR از LOW به HIGH تشخیص داده می‌شود. HC-SR505 خروجی را چند ثانیه HIGH نگه می‌دارد؛ در این فاصله نمی‌توان تک‌تک حرکت‌های فیزیکی را تفکیک کرد. ۳۰ ثانیهٔ اول برای پایدار شدن سنسور نادیده گرفته می‌شود. پیام و بوق کارت نسبت به حرکت هم‌زمان اولویت دارند.

## قطعات کمکی

- دو مقاومت ۱ کیلو‌اهم برای LEDها.
- برای DHT11 خام، مقاومت pull-up حدود ۱۰ کیلو‌اهم بین DATA و 3V3؛ اگر روی ماژول وجود دارد لازم نیست اضافه شود.
- مبدل سطح منطقی دوطرفهٔ مناسب I2C مانند ماژول BSS138 برای LCD پنج‌ولتی.
- ترانزیستور NPN مانند 2N2222، مقاومت پایهٔ ۱ کیلو‌اهم و مقاومت ۱۰۰ کیلو‌اهم بین پایه و امیتر برای بازر کم‌مصرف.
- برای بازر مغناطیسی، دیود هرزگرد مناسب مثل 1N4148 برای جریان کم؛ کاتد به مثبت بازر و آند به کلکتور.
- تغذیهٔ تنظیم‌شده و کابل USB سالم. قبل از تغییر سیم‌کشی برق را قطع کنید.

مبدل CP2102 یا CH340 فقط ارتباط USB/سریال را فراهم می‌کند؛ شمارهٔ GPIO در برنامه را تغییر نمی‌دهد. شمارهٔ پایه را از نوشتهٔ روی برد بخوانید، نه شمارهٔ فیزیکی پین در ردیف.

## اتصالات ESP8266

### RC522 — تغذیه فقط 3.3V

| پایهٔ RC522 | NodeMCU |
|---|---|
| 3.3V | 3V3 |
| GND | GND |
| SDA / SS | D2 = GPIO4 |
| SCK | D5 = GPIO14 |
| MISO | D6 = GPIO12 |
| MOSI | D7 = GPIO13 |
| RST | 3V3 |
| IRQ | بدون اتصال |

SDA روی این کارت‌خوان در حالت SPI نقش SS دارد؛ آن را با SDA نمایشگر اشتباه نگیرید. RST عمداً به 3V3 متصل است؛ کتابخانه با `MFRC522::UNUSED_PIN` از ریست نرم‌افزاری استفاده می‌کند. از سیم‌های کوتاه استفاده کنید. کارت باید سازگار با RC522 و ۱۳٫۵۶ مگاهرتز باشد؛ تگ ۱۲۵ کیلوهرتز قابل خواندن نیست.

### DHT11 و سنسور حرکت

| قطعه / پایه | اتصال |
|---|---|
| DHT11 VCC | 3V3 |
| DHT11 DATA | D1 = GPIO5 |
| DHT11 GND | GND |
| DHT11 NC، در نسخهٔ چهارپایه | بدون اتصال |
| HC-SR505 VCC | 5V تنظیم‌شده |
| HC-SR505 OUT | D0 = GPIO16 |
| HC-SR505 GND | GND همان NodeMCU |

ترتیب پین‌ها را بر اساس نوشته یا دیتاشیت همان قطعه تعیین کنید. در نسخهٔ HC-SR505 معرفی‌شده، تغذیهٔ ۵ ولت و خروجی ۳٫۳ ولت استفاده می‌شود. روی NodeMCUهای مختلف، نام و اتصال پایهٔ VU/VIN/5V متفاوت است؛ برای سنسور از خط ۵ ولت تأییدشده استفاده کنید. ۵ ولت به هیچ GPIO یا پایهٔ 3V3 ندهید.

### LEDها — جهت اتصال مهم است

| LED | مسیر اتصال |
|---|---|
| سبز | 3V3 → مقاومت 1kΩ → آند LED؛ کاتد LED → D4 / GPIO2 |
| قرمز | D8 / GPIO15 → مقاومت 1kΩ → آند LED؛ کاتد LED → GND |

سبز با LOW و قرمز با HIGH روشن می‌شود. این انتخاب با وضعیت بوت GPIO2 (بالا) و GPIO15 (پایین) هماهنگ است. سبز را با اتصال معمول GPIO به آند و کاتد به زمین جایگزین نکنید؛ ممکن است بوت مختل شود. LED داخلی برخی NodeMCUها نیز همراه سبز روشن می‌شود. D3/GPIO0 برای این نسخه آزاد می‌ماند؛ بعداً بدون بررسی وضعیت بوت برای رله استفاده نشود.

## اتصالات ESP32

### LCD از طریق مبدل سطح I2C

| اتصال | مقصد |
|---|---|
| LCD VCC | 5V |
| LCD GND | GND |
| LCD SDA | HV1 مبدل |
| LCD SCL | HV2 مبدل |
| مبدل LV1 | GPIO21 |
| مبدل LV2 | GPIO22 |
| مبدل LV | 3V3 برد |
| مبدل HV | 5V |
| مبدل GND | GND برد |

زمین LCD و مبدل و ESP32 مشترک باشد. رابط‌های I2C نمایشگر معمولاً مقاومت pull-up دارند؛ در حالت تغذیهٔ ۵ ولت، اتصال مستقیمشان به ESP32 مناسب نیست. کتابخانهٔ hd44780_I2Cexp آدرس و آرایش بسیاری از بردهای PCF8574 را خودکار پیدا می‌کند؛ نیازی به حدس 0x27 یا 0x3F نیست. برای خوانا شدن نوشته‌ها پیچ کنتراست پشت LCD را آرام تنظیم کنید.

### گیرندهٔ مادون‌قرمز

| پایهٔ برد گیرنده | ESP32 |
|---|---|
| VCC | 3V3، مشروط به پشتیبانی گیرنده از این ولتاژ |
| GND | GND |
| IN / OUT / S | GPIO27 |

عکس ارسالی مدل دقیق گیرنده و محدودهٔ تغذیه‌اش را مشخص نمی‌کند؛ نوشتهٔ روی قطعه را بررسی کنید. اگر گیرنده فقط با ۵ ولت کار می‌کند، سیگنالش باید با مدار مناسب به حداکثر ۳٫۳ ولت تبدیل شود. ترتیب پایه‌های گیرندهٔ خام را حدس نزنید. ریموت باید باتری داشته باشد و رو به گیرنده باشد.

### بازر دوپایه با ترانزیستور

| اتصال | مقصد |
|---|---|
| GPIO25 | مقاومت 1kΩ، سپس Base ترانزیستور |
| Base | مقاومت 100kΩ به GND |
| Emitter | GND |
| Collector | منفی بازر |
| مثبت بازر | تغذیه متناسب با ولتاژ نامی بازر |

پایه‌های B/C/E در بسته‌بندی‌های مختلف ترانزیستور متفاوت‌اند؛ دیتاشیت همان قطعه را ملاک قرار دهید. این مدار برای بازر کوچک با جریان حدود چند ده میلی‌آمپر است؛ بازر پرمصرف درایور متناسب می‌خواهد. زمین تغذیهٔ بازر و ESP32 مشترک باشد. بازر را مستقیم از GPIO تغذیه نکنید.

صرفاً دوپایه بودن مشخص نمی‌کند بازر اکتیو است یا پسیو. در فایل ESP32 این گزینه را مطابق قطعه تنظیم کنید:

```cpp
const bool ACTIVE_BUZZER = false; // پسیو: تولید صدا با فرکانس
// برای اکتیو مقدار را true کنید؛ تعداد و زمان بوق‌ها ثابت می‌ماند.
```

اگر هر برد با منبع مستقل تغذیه می‌شود، به دلیل ارتباط Wi-Fi لازم نیست زمین دو مجموعه را به هم وصل کنید؛ اما زمین قطعات هر مجموعه باید با همان برد مشترک باشد. خروجی مثبت دو منبع مستقل را به هم متصل نکنید. در استفادهٔ هم‌زمان از USB و تغذیهٔ خارجی، از بازخورانی به USB جلوگیری کنید و مدار تغذیهٔ برد خودتان را بررسی کنید.

## نصب در Arduino IDE

۱. Arduino IDE را نصب کنید. در Preferences، بخش Additional Boards Manager URLs این دو نشانی را وارد کنید:

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
https://arduino.esp8266.com/stable/package_esp8266com_index.json
```

۲. از Boards Manager، بسته‌های `esp32 by Espressif Systems` و `esp8266 by ESP8266 Community` را نصب کنید. این بسته با نسخهٔ 3.0.7 برای ESP32 و نسخهٔ 3.1.2 برای ESP8266 با موفقیت کامپایل شده است؛ جزئیات در VALIDATION.md است. برای شروع همین نسخه‌ها را انتخاب کنید.

۳. از Library Manager این کتابخانه‌ها را نصب کنید:

| کتابخانه | نویسنده | کاربرد |
|---|---|---|
| hd44780 1.3.2 | Bill Perry | LCD |
| IRremote 4.4.1 | Armin Joachimsmeyer و همکاران | ریموت |
| MFRC522 | GithubCommunity | RC522؛ نسخهٔ 1.4.12 |
| DHT sensor library 1.4.6 | Adafruit | DHT11 |
| Adafruit Unified Sensor 1.1.15 | Adafruit | وابستگی DHT |

WiFi، SPI، Wire، Preferences و LittleFS همراه بستهٔ برد هستند؛ کتابخانهٔ جداگانهٔ همنام نصب نکنید.

۴. فایل ZIP را Extract کنید. هر فایل ino را از پوشهٔ هم‌نام خودش باز کنید؛ `Core.h` باید کنار آن بماند.

۵. برای ESP32، برد `ESP32 Dev Module` و پورت درست را انتخاب و `ESP32_Master.ino` را آپلود کنید. برای NodeMCU، `NodeMCU 1.0 (ESP-12E Module)` را انتخاب کنید. در تنظیم Flash Size گزینهٔ ۴ مگابایت با حداقل ۱ مگابایت filesystem را انتخاب کنید، مثلاً `4MB (FS:1MB OTA:~1019KB)`، سپس `ESP8266_Node.ino` را آپلود کنید. در صورت تفاوت واقعی ظرفیت برد، تنظیم را مطابق برد اصلاح کنید.

۶. پس از ذخیرهٔ کارت‌ها، هنگام آپلودهای بعدی گزینهٔ پاک‌کردن کامل فلش را فعال نکنید و اندازهٔ filesystem را تغییر ندهید.

۷. مقدارهای زیر در ابتدای هر دو برنامه دقیقاً یکسان باشند. رمز نمونه را پیش از استفادهٔ واقعی در هر دو فایل عوض کنید:

```cpp
WIFI_SSID = "ESP_Access_System"
WIFI_PASSWORD = "AccessDemo4826"
DEVICE_TOKEN = "access-node-v1-4826"
```

نیازی نیست گوشی یا رایانه به شبکه وصل شود؛ شبکه در این نسخه فقط یک اتصال Wi-Fi را می‌پذیرد و آن اتصال برای ESP8266 است.

## اولین راه‌اندازی، به ترتیب

۱. با برق قطع، سیم‌کشی را انجام دهید. هر برد را با USB یا منبع مناسب روشن کنید.
۲. Serial Monitor مربوط به ESP8266 را با سرعت `115200` و پایان خط `Newline` باز کنید. اگر پیام Storage unavailable مشاهده شد و این **اولین راه‌اندازی روی حافظهٔ خالی** است، `FORMAT` را بنویسید و Enter بزنید. این فرمان همهٔ کارت‌ها/فایل‌های LittleFS را پاک می‌کند؛ در عیب‌یابی یک دستگاه دارای کارت، بی‌دلیل اجرا نکنید.
۳. Serial Monitor مربوط به ESP32 را با سرعت `115200` باز کنید. در اولین بوت، نمایشگر تا ۶۰ ثانیه `Teach remote / Press button 1` نشان می‌دهد. دکمهٔ **۱** ریموت را یک بار بزنید. پیام `Remote key saved` یعنی کد دکمه در حافظه ذخیره شد. اولین فشار فقط آموزش دکمه است، نه ثبت کارت.
۴. اگر فرصت تمام شد یا دکمهٔ اشتباه یاد گرفته شد، حرف `L` را از Serial Monitor به ESP32 بفرستید و دوباره دکمهٔ ۱ را بزنید. کلید ذخیره‌شده با خاموش‌کردن پاک نمی‌شود. پس از تغییر عمدهٔ نسخهٔ IRremote، بهتر است با `L` دوباره آموزش دهید.
۵. صبر کنید اتصال برقرار و اطلاعات DHT11 نمایش داده شود. برای آزمون حرکت حداقل ۳۰ ثانیه صبر کنید.
۶. کارتی نزدیک کنید: در حافظهٔ خالی، باید LED قرمز و `Access Denied` ببینید و سه بوق بشنوید.
۷. کارت را از کارت‌خوان دور کنید. دکمهٔ ۱ را بزنید و منتظر `Scan new card` بمانید. سپس حداکثر تا ۲۰ ثانیه کارت را نزدیک کنید: `Card saved`، LED سبز و دو بوق.
۸. کارت را دور و دوباره نزدیک کنید: `Access Granted` و LED سبز.
۹. هر دو برد را خاموش و روشن کنید؛ همان کارت همچنان باید شناخته شود.
۱۰. کارت ثبت‌نشدهٔ دیگری را امتحان کنید؛ باید رد شود. دوباره ثبت همان کارت قبلی باید `Already saved` نشان دهد.
۱۱. بدون نزدیک‌کردن کارت، ثبت را فعال کنید؛ پس از ۲۰ ثانیه باید لغو شود. برای حرکت دوباره، صبر کنید خروجی PIR ابتدا LOW شود.
۱۲. ESP8266 را خاموش کنید؛ حداکثر چند ثانیه بعد `Node offline` ظاهر شود. پس از روشن کردن، ارتباط باید خودکار برگردد.

## عیب‌یابی

| مشکل | بررسی |
|---|---|
| LCD روشن ولی بدون متن | پیچ کنتراست، اتصال LV/HV، زمین مشترک و SDA/SCL |
| RC522 version برابر 0x00 یا 0xFF | برق 3V3، سیم‌های SPI، SS روی D2، RST روی 3V3 |
| NodeMCU بوت نمی‌شود | جهت LED سبز و قرمز و سطح GPIO2/GPIO15 را بررسی کنید |
| DHT11 no data | DATA روی D1، ترتیب پایه‌ها، pull-up و تغذیه |
| IR هیچ خروجی سریال ندارد | باتری ریموت، جهت گیرنده، مدل و پایه‌ها، ولتاژ مجاز |
| IR پروتکل UNKNOWN دارد | سیگنال قابل شناسایی نیست؛ خروجی سریال و مدل ریموت را بررسی کنید |
| Node offline | یکسان بودن SSID/رمز/token، روشن بودن دو برد و عدم اتصال گوشی به شبکه |
| Storage error | تنظیم filesystem، پیام Serial Monitor و سالم بودن فایل؛ FORMAT پاک‌کننده است |
| بازر بی‌صدا یا فقط تق می‌زند | اکتیو/پسیو، ولتاژ نامی، پایه‌های ترانزیستور و زمین مشترک |

## محدودیت و رلهٔ آینده

این نسخه یک نمونهٔ آموزشی مبتنی بر UID کارت است؛ UID می‌تواند قابل کپی باشد و ریموت نیز احراز هویت مدیریتی قوی ندارد. برای قفل واقعی، طراحی احراز هویت و مدار خروجی باید تقویت شود. CRC تشخیص خرابی تصادفی است، نه امضای امنیتی.

رله در این نسخه فعال نیست. محل افزودن رفتار آن در شاخهٔ کارت مجاز در `scanCard()` مشخص شده است. انتخاب پایه، تغذیه، درایور و زمان فعال‌بودن پس از مشخص شدن مدل رله انجام می‌شود؛ رله را مستقیم به GPIO وصل نکنید.
